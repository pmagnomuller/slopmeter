# Waste audit (slopcop-style gate)

Offline, deterministic rules aligned with the [slopcop](https://github.com/JGalego/slopcop)
catalog (`DEAD001`–`DEAD022`, `TRAIL001`–`TRAIL002`, `VIBE001`–`VIBE026`).
No models, no network at scan time.

The point of the gate is **useful findings**, not a large count. Precision
rules below exist because a first pass over a real services tree mostly flagged
subtitles, generated OpenAPI, optional imports, and `assert 1 in ids`.

## Try it locally

```bash
cd /path/to/slopmeter
pip install -e .          # or: uv pip install -e .
slopmeter rules           # list every rule ID
slopmeter audit .         # whole tree (skips generated + agent dumps)
slopmeter audit --diff    # unstaged + untracked vs HEAD
slopmeter audit --staged
slopmeter audit --base origin/main --history --format github
slopmeter audit --fail-level error   # only fail on errors
```

Exit codes: `0` clean (or below fail-level), `1` findings at/above fail-level, `2` usage error.

Recommended company PR gate: **diff + error**.

```bash
slopmeter audit --base origin/main --fail-level error --format github
```

## What the scanner ignores

These are not “clean code.” They are paths and shapes that are almost never
worth a human looking at:

| Skip | Why |
| --- | --- |
| `.claude`, `.cursor`, `.opencode`, `.agents`, `.codex`, … | Agent worktrees and skill dumps |
| `node_modules`, `vendor`, `dist`, `.venv`, … | Vendored / build output |
| `**/docs/docs.go`, `*.pb.go`, `*_gen.go`, `*.min.js`, snapshots | Generated |
| File header `Code generated by` / `DO NOT EDIT` | Generated even with an odd name |
| `## Section` then `### Subtitle` | Outline, not an empty doc |
| `except ImportError: pass` / `FileNotFoundError: pass` | Optional dependency / missing file |
| `except ValueError: return None` | Parse-or-default |
| `assert 1 in ids` | Real membership check (`assert True` still fails) |
| `print()` then `sys.exit()` in a CLI handler | Not a swallowed exception |
| `// Step 1: the root span…` in tests | Explains the algorithm |
| `__exit__(self, *args): pass` | Context-manager protocol |
| Regex / string literals that mention `TODO` | Rule source, not a stub |
| Em dashes / uniform paragraphs in short or table-heavy READMEs | Structure, not vibe padding |

## GitHub Action

In any repo:

```yaml
name: waste
on: [pull_request]
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: pmagnomuller/slopmeter@main   # pin a tag/SHA in production
        with:
          base: ${{ github.base_ref }}
          fail-level: error
          history: true
```

### Inputs

| Input | Default | Meaning |
| --- | --- | --- |
| `base` | _(empty)_ | Diff `BASE...HEAD`. Empty scans `paths` (default `.`) |
| `fail-level` | `warning` | `info` / `warning` / `error`. Use `error` on company PRs. |
| `history` | `true` | Also TRAIL-check commit subjects in the range |
| `paths` | `.` | Used when `base` is empty |
| `version` | Action SHA | Override pip install ref if not using the Action checkout |
| `python-version` | `3.12` | setup-python version |

PR annotations use `--format github`.

## Rule catalog

### Deadweight (code)

| ID | Sev | Fires on | Quiet on |
| --- | --- | --- | --- |
| `DEAD001` | error | `except Exception: pass` / empty `catch {}` | Specific types (`ImportError`, `ValueError`, `httpx.HTTPError`, …) |
| `DEAD002` | warning | `TODO` / `FIXME` / `HACK` / `XXX` in production comments | Tests |
| `DEAD003` | error | `raise NotImplementedError("TODO:…")`, `panic("TODO")` | Bare `NotImplementedError`, regex source strings |
| `DEAD004` | warning | Broad except that returns `None` / `[]` / `{}` | `except ValueError: return None` |
| `DEAD005` | warning | Empty `def hook(): pass` | `__init__` / `__exit__` / `abstractmethod` |
| `DEAD006` | info | Comment that restates the next identifier | — |
| `DEAD007` | warning | Identical substantial comments repeated | — |
| `DEAD008` | info | Wrapper that only forwards to the same name | — |
| `DEAD009` | warning | `if x: return True` / `else: return False` | Same literal both sides |
| `DEAD010` | error | `assert True` / `assert 1` as the whole statement | `assert 1 in ids` |
| `DEAD011` | warning | 10 identical substantial lines in one file | Generated files; JSON/string-heavy swagger blocks |
| `DEAD012` | warning | Markdown heading with no body and no deeper subtitle | `## Parent` / `### Child` outlines |
| `DEAD013` | info | Hard-coded inventory counts in prose (“we have N endpoints”) | — |
| `DEAD014` | warning | Broad except whose body is only `raise` | `except SystemExit: raise`, specific types |
| `DEAD015` | warning | Broad except whose **only** body is `print(...)` | `print` then `sys.exit` / extra body; `KeyboardInterrupt` |
| `DEAD016` | error | Empty JSX `onClick={() => {}}` | Tests |
| `DEAD017` | warning | `handleSubmit` that only `return { ok: true }` | Tests |
| `DEAD018` | warning | Decorative `# --- Phase 1 ---` banners (2+) | `Step 1:` explaining an algorithm; tests |
| `DEAD019` | error | Bare `except:` with a real body | `except: pass` (that is `DEAD001`) |
| `DEAD020` | error | Go `if err != nil { }` | `if err != nil { return err }` |
| `DEAD021` | warning | “this is a stub” / “implement later” leftovers | Tests |
| `DEAD022` | error | `breakpoint()`, `pdb.set_trace()`, `debugger;` | Tests |

### Papertrail (commits)

| ID | Sev | Fires on |
| --- | --- | --- |
| `TRAIL001` | warning | Subject `WIP` / `fix` / `tmp` / `update` / empty |
| `TRAIL002` | error | `fixup!` / `squash!` / `amend!` on the integration branch |

### Vibecheck (prose)

Density rules on markdown/rst/txt. Chatbot disclaimers (`VIBE019`) still fire
on a single hit. Shape rules (`VIBE007` em dashes, uniform paragraphs,
restatement) stay quiet on table/list/heading-heavy READMEs.

`VIBE001`–`VIBE026` cover stock transitions, assistant framing, hedges,
both-sides templates, structure announcements, staged reveals, repeated
openings, abstract triads, metaphors, promo language, correlatives, jargon,
and paraphrasing the reader’s question.

## Company rollout tips

1. Start with `fail-level: error` on `BASE...HEAD`. Deadweight hard-fails;
   vibe stays warning.
2. Pin the Action to a tag/SHA; or vendor `waste.py` if supply-chain policy
   requires it.
3. Pair with the observatory: `slopmeter --org …` for trends, Action for new
   waste on the diff.
4. Do not “fix” generated `docs.go` or agent worktrees. The scanner already
   skips them.
5. A `DEAD012` after this release means the heading really has no body.
